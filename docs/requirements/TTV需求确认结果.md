# TTV 需求确认结果

来源：`D:/Users/kioco/Downloads/ttv-需求回答.json`

## 1. 已确认方向

### 产品定位

- 首个产品同时面向个人自用和开源 LumiPlayer 类似产品。
- 首发平台为 Windows，其他平台后续考虑。
- 目标不是复制源码，而是实现功能等价和同类能力。
- 首次交付采用安装程序，并发布 GitHub Release。
- 项目使用独立仓库。

### 播放核心

- 采用推荐的 `libmpv.dll` 动态链接方案。
- 播放器使用独立播放窗口。
- v1.0 需要覆盖本地文件、HTTP 直链、HLS、DASH、HDR、硬件解码、倍速、截图和画中画。
- 音频包含单音轨、多音轨切换、音量/增益、WASAPI 独占、5.1/7.1 和音频延迟。
- 字幕包含外挂、内嵌、切换、样式、延迟、在线下载和 OpenSubtitles。
- 播放历史保存媒体 ID、位置、总时长、完成比例、最近播放时间、音轨、字幕轨和播放设置。
- 播放失败采用：重试 → 刷新 Provider → HLS/转码代理 → 外部播放器 → 明确错误。
- 保留外部播放器唤起能力。

### 媒体库与数据

- v1.0 媒体库覆盖本地目录、NAS/SMB、WebDAV、Emby、Jellyfin、Plex 和云盘，另补充光鸭云盘。
- 扫描方式：定时扫描、文件系统监听、手动扫描、增量扫描。
- 媒体类型覆盖电影、电视剧、动漫、纪录片、演唱会、综艺、音乐、直播，以及用户补充类型。
- 兼容 Jellyfin/Emby/TMDB 常见命名规则。
- 元数据来源：TMDB、MDBList、Emby/Jellyfin、本地 NFO、自建服务。
- 额外考虑 JavBoss 和 Stash 的刮削能力。
- 使用独立 SQLite，不直接复用 StreamHub/lumi-store.db。
- 迁移范围包括播放历史、媒体库、账号、云盘配置和播放器设置。

### Provider 与媒体服务器

- Provider 目标为全部已发现 Provider：百度、阿里、夸克、115、天翼、光鸭、飞牛、Emby、Jellyfin、Plex。
- 云盘同时支持二维码 OAuth 和 token 导入；OAuth 失败时 token 作为备用方案。
- 凭据使用推荐的系统级保护方案。
- Provider 采用统一可插拔接口。
- 直链解析采用可配置 endpoint、HTTPS 和本地直连优先。
- Emby/Jellyfin/Plex 首版支持登录、浏览、PlaybackInfo、直链、转码、播放进度回写和字幕。

### UI 与播放页

- 顶部导航为主，结合 macOS 风格。
- 播放页使用独立路由和独立窗口。
- 播放页需要控制条、播放列表、清晰度、音量、选集、收藏和设置。
- 设置包含字幕、音轨、补帧、超分、播放器内核选择以及后续视频调节能力。
- 视觉方向同时考虑深色影院和浅色简洁主题。
- 当前暂无参考截图或录屏，需要后续通过实现过程确定视觉稿。

### AI、增强与插件

- 全面的 AI 功能规划放到 v4.0。
- v1.0 先做视频增强类 AI。
- AI 接口优先采用 OpenAI 兼容 API。
- 视频增强和插件体系按“开启”处理，需设计可插拔、可关闭和零开销路径。

### 账号与授权

- v1.0 采用单机无账号。
- License 采用完全免费模式。
- 因此第一版不需要账号注册、在线激活、订阅、设备绑定或 License 服务。

### 更新与部署

- 更新采用差分包。
- 更新失败需要回滚。
- 运行保持 0 外部依赖，不能要求用户预装 Java 21 等运行时。
- 更新服务器、域名、对象存储和 CDN 尚未确定。

### 工程与验收

- 技术栈确认方向为 Tauri + Rust + TypeScript + React/Svelte。
- 仓库采用独立仓库。
- 验收包含单元测试、集成测试、播放样本集、断网测试、4K/HDR 测试和长时间稳定性测试。
- 性能第一原则是播放速度快、秒加载和长期稳定。
- 第一批样本：光鸭云盘视频资源 + 电脑本地视频。

## 2. 推荐的 v1.0 范围

```text
Tauri Desktop
├── Rust Core
│   ├── libmpv 播放服务
│   ├── 本地媒体扫描与监听
│   ├── Provider 抽象层
│   ├── Windows 凭据存储
│   └── 独立 SQLite 数据库
├── TypeScript UI
│   ├── 顶部导航
│   ├── 媒体库 / 搜索 / 收藏 / 继续观看
│   ├── 独立播放窗口
│   └── 播放器设置
├── 首批 Provider
│   ├── 本地文件 / NAS / WebDAV
│   ├── Emby / Jellyfin / Plex
│   └── 光鸭云盘优先，其余 Provider 依次接入
└── 质量保障
    ├── 播放样本集
    ├── 断网与失败降级
    ├── 4K/HDR
    └── 长时间稳定性
```

## 3. 仍需补齐的关键问题

1. Windows 最低版本是 Windows 10 还是 Windows 11？是否要求便携版？
2. v1.0 是否包含全部 Provider，还是先把光鸭、Emby/Jellyfin/Plex 做成第一批？全部接入会显著拉长周期。
3. “0 外部依赖”是否包含不内置 Java、Python、VapourSynth、FFmpeg 和 mpv 运行库？这些组件需要随安装包一起打包。
4. 差分更新服务器放在哪里？需要域名、对象存储、CDN 和签名/校验策略。
5. TypeScript 前端最终选 React 还是 Svelte？
6. 深色影院和浅色简洁是双主题同时提供，还是先选一个主主题？
7. JavBoss/Stash 刮削是否只做适配器，还是需要直接内置完整刮削流程？
8. “视频增强类 AI”v1.0 的第一项具体功能是 RIFE 补帧、超分、锐化、HDR 还是自动画质策略？
9. “秒加载”目标需要量化：冷启动、首帧、媒体库打开和远程直链首帧分别要求多少秒？
10. 是否需要提供测试用光鸭账号/测试资源，或者先用 mock Provider 开发？

## 4. 下一步建议

先冻结以下四项，再开始搭建工程：

1. Windows 最低版本和发布包形态。
2. v1.0 Provider 首批范围。
3. React 或 Svelte 二选一。
4. v1.0 第一项视频增强功能。

冻结后即可进入：项目初始化 → Rust/libmpv 播放闭环 → SQLite 媒体库 → 独立播放窗口 → Provider 接口 → 首批 Provider → 测试和打包。
