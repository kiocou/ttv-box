# TTV 总体技术架构与系统设计规范

> **架构原则**：单进程编排、双窗口联动、纯 Rust 高性能底层、纯 React 现代化前端、零外部运行环境依赖。

## 2. 核心子系统职责

### 2.1 多窗口与生命周期管理器 (`WindowManager`)
- **主窗口 (`main`)**：无边框设计（`decorations: false, transparent: true`），macOS 风格交通灯与导航栏，负责媒体库浏览、云盘探索与系统设置。
- **独立播放窗口 (`player`)**：点击媒体卡片或云端视频时独立拉起（`index.html?window=player`），拥有独立的 Direct3D 11 渲染通道与沉浸式全屏控制。

### 2.2 Provider 路由与解析引擎 (`ProviderRouter`)
- 采用 Rust 抽象 `trait MediaProvider`，负责统一不同来源的数据规范与播放地址协商：
  ```rust
  #[async_trait]
  pub trait MediaProvider: Send + Sync {
      fn provider_id(&self) -> &'static str;
      async fn request_device_code(&self) -> Result<DeviceCodeResponse, ProviderError>;
      async fn poll_device_token(&self, device_code: &str) -> Result<Option<Session>, ProviderError>;
      async fn login_sms(&mut self, phone: &str, code: &str, vid: &str) -> Result<Session, ProviderError>;
      async fn list_files(&self, parent_id: Option<&str>) -> Result<Vec<MediaItem>, ProviderError>;
      async fn resolve_playback(&self, item_id: &str) -> Result<PlaybackDescriptor, ProviderError>;
      async fn refresh_session(&mut self) -> Result<Session, ProviderError>;
  }
  ```
- **`resolveProvider` 状态机**：维护 `cache-hit` 缓存快速起播、`fast-start-raw-url` 直播直连、`fallback` 自动回退与重试机制。

### 2.3 播放引擎 (`PlaybackActor`)
- 采用 **Actor 模型** 封装 `libmpv`，通过专有 Tokio 任务与通道隔离 C ABI 阻塞调用。
- 通过 Windows API 获取窗口句柄 HWND，注入 `wid=<HWND>`，实现 Direct3D 11 高性能硬件加速与 Perceptual HDR 色调映射。

### 2.4 AI 画面增强管线 (`EnhancementEngine`)
- 包含两大管线：
  1. **光流插帧 (MEMC)**：通过 VapourSynth 调用 DirectML + ONNX Runtime 运行 RIFE v4.25 lite 模型。
  2. **神经网络超分辨率 (SR)**：通过 mpv 着色器链加载 `SSimDownscaler.glsl`、`ArtCNN.glsl`、`adaptive-sharpen.glsl`。
- **零外部依赖保障**：打包自带 embedded Python 3.12、`libvapoursynth.dll`、DirectML、ONNX Runtime 与 ONNX 模型文件。

### 2.5 存储与安全引擎 (`StorageEngine`)
- **本地 SQLite**：激活 WAL 模式与 FTS5 全文索引，单库统一管理媒体源、元数据、播放进度与 KV 配置。
- **Windows DPAPI**：调用 `CryptProtectData` 对 Access Token、Refresh Token、云盘密钥进行 OS 账户级硬件绑定加密。
