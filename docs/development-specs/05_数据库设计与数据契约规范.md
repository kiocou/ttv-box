# TTV 数据库设计与数据契约规范

> **规范原则**：单 SQLite 文件统一管理、WAL 模式高并发写入、FTS5 全文毫秒级检索、Windows DPAPI 硬件级凭据加密。

---

## 1. 数据库物理配置与 PRAGMA 规范

```sql
PRAGMA journal_mode = WAL;          -- 开启 Write-Ahead Logging，读写完全互不阻塞
PRAGMA synchronous = NORMAL;        -- 兼顾断电安全性与极致磁盘写入性能
PRAGMA foreign_keys = ON;           -- 保证逻辑完整性
PRAGMA busy_timeout = 30000;        -- 30 秒超时等待，杜绝 database is locked 错误
PRAGMA temp_store = MEMORY;         -- 临时表与排序在内存中执行
```

## 2. 核心数据表 DDL 权威规范

### 2.1 媒体主表 (`media`) 与全文检索表 (`media_fts`)
```sql
CREATE TABLE IF NOT EXISTS media (
    id TEXT PRIMARY KEY,                            -- 唯一 GUID 或云盘 FileID
    account_id TEXT,                                -- 关联云盘账号 ID (可选)
    library_id TEXT,                                -- 所属媒体库 ID
    kind TEXT NOT NULL,                             -- 'movie' | 'tv' | 'episode' | 'video'
    title TEXT NOT NULL,                            -- 主标题 (如: 沙丘 2)
    original_title TEXT,                            -- 原语种标题 (如: Dune: Part Two)
    sort_key TEXT,                                  -- 拼音/首字母排序键
    year INTEGER,                                   -- 上映年份 (如: 2024)
    art_url TEXT,                                   -- 海报海报图 URL / 本地缓存路径
    backdrop_url TEXT,                              -- 横幅背景图 URL
    rating REAL,                                    -- 评分 (如: 8.6)
    duration_seconds INTEGER,                       -- 总时长 (秒)
    source_type TEXT NOT NULL DEFAULT 'local',      -- 'local' | 'guangya' | 'emby' | 'webdav'
    remote_path TEXT,                               -- 物理或云端路径
    payload JSON,                                   -- 扩展元数据 (演职员/音轨/字幕列表 JSON)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 分页与高效排序覆盖索引 (消除 filesort)
CREATE INDEX IF NOT EXISTS idx_media_page 
ON media(account_id, library_id, kind, sort_key, id);

-- 路径去重与索引
CREATE INDEX IF NOT EXISTS idx_media_source_path 
ON media(source_type, remote_path);

-- FTS5 全文检索引擎表 (支持中英文 unicode61 分词)
CREATE VIRTUAL TABLE IF NOT EXISTS media_fts USING fts5(
    title,
    original_title,
    id UNINDEXED,
    tokenize='unicode61'
);

-- 自动同步触发器
CREATE TRIGGER IF NOT EXISTS trg_media_insert AFTER INSERT ON media BEGIN
    INSERT INTO media_fts(id, title, original_title) VALUES (new.id, new.title, new.original_title);
END;

CREATE TRIGGER IF NOT EXISTS trg_media_delete AFTER DELETE ON media BEGIN
    DELETE FROM media_fts WHERE id = old.id;
END;
```

### 2.2 观看历史与播放进度表 (`watch_history`)
```sql
CREATE TABLE IF NOT EXISTS watch_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    media_id TEXT NOT NULL,
    position_seconds REAL NOT NULL,                 -- 当前播放进度 (秒)
    duration_seconds REAL NOT NULL,                 -- 总时长 (秒)
    completed INTEGER NOT NULL DEFAULT 0,           -- 是否观看完毕 (0/1)
    watched_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (media_id) REFERENCES media(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_history_media ON watch_history(media_id, watched_at DESC);
```

### 2.3 键值存储与会话表 (`kv`)
```sql
CREATE TABLE IF NOT EXISTS kv (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,                            -- JSON 或普通字符串
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 3. Windows DPAPI 凭据加密模型

所有云盘与媒体服务器的 Access/Refresh Token 均在 Rust 内存中通过 Windows DPAPI 加密后存入 `kv` 表：

```rust
// 保存凭据
pub fn save_session(db: &Database, key: &str, session: &Session) -> Result<()> {
    let plain_bytes = serde_json::to_vec(session)?;
    let encrypted_bytes = Dpapi::encrypt(&plain_bytes)?;
    let base64_str = base64::encode(encrypted_bytes);
    db.kv_set(key, &base64_str)?;
    Ok(())
}

// 读取凭据
pub fn load_session(db: &Database, key: &str) -> Result<Option<Session>> {
    if let Some(base64_str) = db.kv_get(key)? {
        let encrypted_bytes = base64::decode(&base64_str)?;
        let plain_bytes = Dpapi::decrypt(&encrypted_bytes)?;
        let session: Session = serde_json::from_slice(&plain_bytes)?;
        Ok(Some(session))
    } else {
        Ok(None)
    }
}
```
